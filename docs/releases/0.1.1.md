# v0.1.1 — Clearer project setup guidance

> **Status: prepared for release; npm publication pending.** When creating the GitHub Release, replace this with **Source release available; npm publication pending.** Update it after registry verification succeeds.

## Fixes

- When package.json is missing, setup explains how to run `npm init -y`, then `npx axios-scaffold-kit init`.
- Existing-project users are directed to the folder containing their manifest.
- Setup still stops before consent, installation, or generation. Existing project files remain untouched, including with `-y` or `--yes`.
- Other manifest read errors and malformed JSON retain their existing handling.

## Documentation

- Added installation steps for empty folders and clarified the published package's status.
- Shortened contributor verification guidance and updated the initial-release notes.

## Breaking changes and migration

None. Generated API/authentication files are unchanged; existing applications need no code changes. Future invocations of the updated CLI receive the improved message. Previously installed development copies need a normal package update.

## Installation

After this patch is published, run from a project containing package.json:

```sh
npx axios-scaffold-kit@0.1.1 init
```

For a new empty folder, run `npm init -y` first.
