# v0.1.0 — Initial JavaScript release

> **Status: prepared for release; GitHub tagging and npm publication pending.** When publishing the GitHub Release before npm, use **Source release available; npm publication pending**. Remove the pending status only after npm publication and registry checks succeed.

## Summary

axios-scaffold-kit generates an editable Axios API starter in an existing JavaScript project. Connect your endpoints and optionally configure your backend's authentication, refresh, and CSRF handling.

## Added

- `init`, `init -y`, `init --yes`, and help, with Node.js 16+ CLI support.
- Four local files: a shared client, example API methods, editable authConfig, and a commented interceptor implementation.
- GET, POST, PUT, PATCH, and DELETE examples with query/body/request-option forwarding. Example methods return response.data; the client preserves full responses.
- Optional bearer-token lookup, shared refresh with one retry per request, public bypass, independent CSRF hooks, cancellation, fixed-origin filtering, and cleanup. Empty default configuration enables no authentication.
- Installation consent when Axios is missing, preservation of existing direct declarations, and output checks before npm or writes.
- User guides with copyable customization recipes, contributing guidance, and read-only CI configuration.

## Fixes

- Authentication recipe checks and the browser fixture accept Unix and Windows documentation line endings.

## Breaking changes

This is the initial version; there is no previous published version to upgrade. Earlier local prototypes using configureAuth.js/configureAuth should follow the manual naming guidance in the authentication guide.

## Limitations

- JavaScript ES modules; fixed src/api output. TypeScript and configurable output are future work.
- Automatic installation supports standalone npm projects. Workspace/Yarn/pnpm installation requires the developer's existing workflow.
- Backend endpoints, token storage, refresh persistence, cookie/CORS rules, and CSRF acquisition remain application responsibilities.
- Existing Axios declarations are not upgraded. Optional authentication uses the public AxiosHeaders API, verified locally with Axios 1.20.0.
- npm may update target metadata, lockfiles, and dependencies after consent. Failed installation or partial generation does not promise rollback.
- Only claim remote CI/platform results after their jobs actually pass; consult the README for recorded local verification.

## Actions for existing applications

Nothing is automatically rewritten. Review generated templates and integrate changes manually; setup refuses to overwrite existing generated destinations. New generator versions do not upgrade existing application code.

## Installation

After npm publication is confirmed:

```sh
npx axios-scaffold-kit@0.1.0 init
# Explicitly authorize installing missing Axios:
npx axios-scaffold-kit@0.1.0 init -y
```

The generator's download prompt and Axios installation consent are separate. See the README for where to edit base URLs, endpoints, and optional authConfig hooks.
